# Antenna Intervention Monitoring

Laravel 13 / PHP 8.4 / PostgreSQL 17 API and dashboard to monitor antennas and their maintenance interventions.

## Technical choices

### Architecture and Docker

The application is containerized using Docker Compose. The architecture is as follows:
- `php`: PHP 8.4 with Laravel 13, running on php-fpm
- `nginx`: Nginx serving the application
- `postgres`: PostgreSQL 17 for the database
- `node`: Node.js for building the frontend assets
- `vite` (`dev` profile): Vite dev server with hot reload, started with `make dev` (port 5173).

### Backend

I decided to use Laravel as backend framework. It's a mature and robust framework suited for scaffolding APIs and handling database operations efficiently.
It gives a flexible boilerplate to extend the project with tools like Vite for frontend asset management.

#### Clean architecture

As the project is supposed to handle more than 100 000 antennas and interventions, I chose to follow a clean architecture approach.
With this amount of antennas, there could be various types of antennas and type of interventions needed. Clean architecture allows for better separation of concerns and easier testing.

#### Atomicity and concurrency

To guarantee atomicity, multiple verification steps are made at different layers.
- Foreign key constraints are used to ensure data integrity at the database level, the index `uq_one_active_intervention_per_antenna` ensures that only one intervention can be active per antenna.
- Prior to inserting a new intervention, the application checks if the antenna exists and if the intervention type is valid.
- The application injects a `TransactionManager` that wraps the load, check, insert and status update operations in a single transaction.

### Frontend

Vite is used for building the frontend assets. It's amongst the most popular frontend build tools and the vite ecosystem is very powerful.
It allows me to use scss with bem naming convention for styling.

## Stack

| Concern | Choice |
|---|---|
| Backend | Laravel 13, `declare(strict_types=1)` everywhere (enforced by Pint) |
| Database | PostgreSQL 17, Eloquent ORM + migrations |
| Auth | Static Bearer token (`API_TOKEN`) on write routes, see `App\Http\Middleware\EnsureApiTokenIsValid` |
| API docs | OpenAPI generated by [Scramble](https://scramble.dedoc.co) |
| Frontend | Blade + SCSS (Bootstrap 5) built by Vite, native `fetch` |
| Tests | PHPUnit feature tests against a dedicated PostgreSQL database


## Getting started

```bash
docker compose up --build
```

On first start the containers will install Composer dependencies, create `.env` from `.env.example`, generate `APP_KEY`, build the assets and run the migrations.

- Dashboard: http://localhost:8080
- API: http://localhost:8080/api
- OpenAPI UI: http://localhost:8080/docs/api

### Migrations

To create the tables using migrations, run:

```bash
make migrate
```

### Seeding

To seed the database with mock antennas mock data, run:

```bash
make seed

```
### Testing

To run the tests, run:

```bash
make test
```
